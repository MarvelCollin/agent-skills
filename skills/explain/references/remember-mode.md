# Remember

For `remember <thing>`, or when the user asks how to remember or memorize something: a template, a formula, a list, steps, vocabulary, definitions or a speech. Every reply still follows rules E1 to E14 in [explain-rules.md](explain-rules.md).

Rereading and highlighting feel like learning but are the weakest techniques. What makes memory last is understanding the meaning, recalling from memory with feedback, and spacing that recall over days. This mode turns the material into exactly that.

## First reply

1. **Get the material.** Use what the user pasted or the file they named. If nothing was given, ask for it in one line.
2. **Meaning first.** If the user may not understand what they are memorizing, explain it briefly with the shape from SKILL.md. People remember what they think about, and memorizing words without meaning fades fast.
3. **Build the logic map.** Split the material into 3 to 5 chunks. For each chunk, give its job in plain words and its parts in order, as a short chain with arrows. Put it in a table:

   | Chunk | Its job | The chain | Cue words |
   |-------|---------|-----------|-----------|

   Cue words are the first one or two words of each line or step. The chain is the logic that links them: "claim → why → result → example → so". When the order has a reason, say the reason. A chain with reasons is far easier to recall than a list.
4. **Add a hook only where order is arbitrary.** For a list whose order has no logic (planet names, the OSI layers), give one short mnemonic. Tie it to the meaning when you can. Never use a mnemonic in place of understanding.
5. **Show the four levels** they will practise, using one chunk of their own material as the example:
   1. Full text, copied once while saying what each part does
   2. Cue words only
   3. The chain only
   4. Blank page
6. **Give the schedule.** Short recall sessions of 5 to 10 minutes on day 1, 2, 4, 7, 14 and 30. Each session starts with a blank page, not with rereading.
7. **Start the first drill.** Ask them to write chunk 1 from level 2 (cue words) now, from memory. One chunk, one request.

Keep the first reply as short as the material allows. If the user says "just the plan", stop after step 6.

## Drills

When the user sends their attempt:

1. Compare it with the original. Say what they got right first, specifically and briefly.
2. Show what is missing or wrong, word for word, and say which link in the chain it belongs to so the logic helps them next time.
3. Decide the next step:
   - All right: move this chunk up one level, or move to the next chunk at level 2
   - Mostly right: repeat the same level once, starting with the missed part
   - Mostly wrong: go down one level
4. Aim for attempts that are about 8 in 10 right. Recall only builds memory when it mostly succeeds and gets feedback.
5. One request per turn. Never a list of drills at once.

When every chunk reaches level 4, ask for the whole thing on a blank page.

## Use it, not just recite it

Memory that only recites breaks under pressure. Once they can write it from a blank page, practise using it with new content:

- **Templates** (essays, emails, speeches): give a fresh topic and ask them to fill every slot in a set time. Use a different topic each time. Warn that slots filled with vague content score badly, so the content must fit the question
- **Formulas and steps**: give a new problem that needs them
- **Vocabulary and definitions**: ask for their own sentence or a new example
- **Lists**: ask a question that needs one item from the middle of the list

## Optional flashcards

If they use flashcards, offer cloze cards built from the cue words, with one gap per card: "Not only can this ___, but it can also ___." Do not offer cards for the whole text at once.

## Coming back

At the end of a session, say which chunks are solid and which one to start with next time. Suggest `/explain remember` again on the schedule days, or `/explain quiz` for a quick check.
