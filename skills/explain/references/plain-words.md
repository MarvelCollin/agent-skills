# Plain Words

Swap hard words for plain ones before you send. Aim for words a 12 year old knows, and keep sentences under 20 words. GOV.UK writes for a reading age of 9, even for specialists, and 80 percent of people prefer it.

## Never write

These make a stuck reader feel slow, or add nothing.

| Type | Words and phrases |
|------|-------------------|
| Makes the reader feel slow | simply, just, obviously, clearly, basically, of course, easy, trivial, it's easy to see |
| Praise and cheer | great question, good question, excellent, I'd be happy to, let's dive in, exciting, emoji, exclamation marks |
| Talk about the explanation | it's important to note, it's worth mentioning, at its core, in simple terms, in a nutshell, let me explain, to put it simply, in summary, to sum up |
| Empty endings | does that make sense, any questions, got it, hope this helps, let me know if you have questions, feel free to ask |
| Reflex hedges | somewhat, relatively, arguably, generally speaking, may potentially, it could be said |
| Empty intensifiers | very, extremely, incredibly, crucial, powerful, fundamental, essential |

Hedge only where there is real doubt, and say what the doubt is: "this is true on Windows, not on Mac".

## Swap

| Instead of | Write |
|------------|-------|
| utilize, leverage, employ | use |
| facilitate, enable | help, let, or say how |
| commence, initiate | start |
| terminate | end, stop |
| prior to | before |
| subsequent to | after |
| in order to | to |
| in the event that | if |
| approximately | about |
| sufficient | enough |
| numerous | many |
| demonstrate | show |
| obtain, acquire | get |
| require | need |
| modify | change |
| indicate | show, mean |
| component | part |
| functionality | what it does |
| mechanism | how it works |
| paradigm, framework, approach, model, landscape, ecosystem | name the actual thing |
| robust | strong, or say against what |
| scalable | still works with many more users, or say how many |
| seamless | smooth, or delete |
| optimal | best |
| under the hood | inside |
| out of the box | by default |

## Verbs, not nouns made from verbs

| Instead of | Write |
|------------|-------|
| perform an analysis of | analyze |
| make a decision | decide |
| provide assistance | help |
| carry out an investigation | investigate |
| the implementation of caching | adding a cache |
| conduct a comparison | compare |

## Hard words you need

Some technical words the user will need later. Keep them, but:

1. Explain the thing in plain words first, then give the name: "...and that is called a deadlock."
2. Or define it in the same sentence where it first appears: "an index, a sorted shortcut list the database keeps,".
3. Spell out and explain acronyms: "the TTL, how long a saved copy stays valid".
4. Never explain a hard word with another hard word. "A mutex is a synchronization primitive" explains nothing.
5. Use one name for one thing. Do not switch between "function", "method" and "routine" for the same thing.

## Numbers

Turn big or abstract numbers into sizes people can picture. "A few milliseconds, faster than a blink" beats "3 ms". "About as heavy as a cat" beats "5 kg". Round numbers unless the exact value matters.

## Other languages

When the user writes in another language, the same rules apply in that language: common everyday words, short sentences, the technical term in its usual form (often the English word) with a plain explanation the first time.
