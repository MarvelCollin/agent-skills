# Onboarding and Help

Getting a new user to their first success, and helping anyone who gets stuck later. Design the product so it needs little explaining, then explain in context.

## First Run

- Ask two or three questions that change what the user sees (role, team size, main goal), each skippable. Not a survey
- Land on a useful home with a setup checklist, not on an empty dashboard
- Offer sample data or a template so the product is not empty, clearly marked and easy to delete
- The first success should take minutes: create the first class, invite the first student, send the first invoice

## Setup Checklist

- 3 to 6 tasks named with verbs ("Add your first class"), each linking straight to where it is done, with done states and overall progress
- Completes itself when the user does the task anywhere in the product
- Dismissible, and reachable again from help

## Contextual Help over Tours

- Avoid product tours on first load. Users skip them and forget them
- Teach in the moment: empty states that explain the space, a hint when the user first opens a feature, an inline example in a field
- One hint at a time, short, dismissible, never covering what it explains, and never shown again once dismissed
- New features get a small "New" marker and a one line explanation when the user reaches them, not a pop up on login

## Help Access

- A help menu in the top bar: search help articles, keyboard shortcuts, contact support, what's new, status page
- Popup tips (an `i` or `?` button that opens on click) for unfamiliar fields, with a link to more
- Error states link to the relevant help article
- Support contact shows response time and lets the user attach context automatically (page, workspace)

## Check

1. Can a new user reach a first success without reading anything?
2. Is any information the user needs to finish a task hidden in a tour or a tooltip only?
3. Can dismissed help be found again?
